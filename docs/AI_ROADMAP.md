# 策略目标、评估与学习接入条件

更新时间：2026-10-31

## 两个独立目标

- 对局策略：给定棋盘、手牌、剩余牌组、回合、SP 和对手上下文，输出合法卡牌、动作模式、旋转与位置。策略比较时固定牌组和场景。
- 反制牌组搜索：给定 NPC、等级、场地、当前策略和卡池限制，筛选完整的 15 张牌组。实现及运行方式见 [DECK_SEARCH](DECK_SEARCH.md)。

当前分支已有规则模拟、Random / Greedy / MCTS、自对弈 JSONL、续跑和牌组搜索。搜索实现见 [MCTS](MCTS.md)，代理边界见 [RULES](RULES.md)；尚无本项目已训练完成的持久化策略或价值模型。

## 评估约定

以下是项目的评估要求，不能当作已完成的验收结果：

1. 固定 seed 集合、牌组、场地、双方策略与搜索预算，并交换 A/B 两侧比较。
2. 分别记录非法行动、胜负、分差、决策耗时，以及各 NPC / 等级 / 场地分组结果。
3. 牌组筛选与最终复测使用不同的 seed 和留出场景，保留完整配置与样本数。
4. 对手池扩展、历史策略快照与真实 NPC 行为拟合属于后续工作，不能把候选模型说成已实现。
5. 离线 NPC 是代理策略；离线结果用于工程检查和候选筛选，实机效果另行验证。

## 决策原则

是否引入深度学习，以 Nintendo Switch 实机对局数据为准，不以离线代理胜率或主观印象决定。

MCTS 已能作为第一阶段正式策略。离线自对弈用于发现规则错误、验证数据链路和筛选候选配置，但不能证明真实 NPC 胜率。

## 必须先完成的链路

1. EasyCon 在真实 Switch 上完成逐键、双摇杆、断线和中性状态验证。
2. 采集卡画面能够识别菜单、选牌、棋盘、手牌、SP、预览和结算界面。
3. MCTS 能在完整自动流程中输出合法动作。
4. 每次输入执行后能通过画面确认是否成功。
5. 实机对局记录能够区分 AI 失败、视觉失败和控制器失败。

如果把识别错误或执行未确认的数据当成正确样本，模型会收到错误监督。
这是本项目的数据质量风险，不能通过更换搜索算法自动消除。

## 实机测试配置

第一轮固定一套配置：

- 策略：Greedy 与 MCTS 分别测试。
- MCTS：先固定模拟数和时间上限。
- NPC：从低等级开始，通过后再测试等级 3。
- 场地与牌组：覆盖至少多个 NPC 牌组和不同形状场地。
- seed：离线评估固定，实机牌序按实际游戏记录。
- 每局保存完整日志和失败截图。

## 记录字段

- 对局 ID、日期、NPC、等级、场地、NPC 牌组。
- 我方牌组及卡牌顺序。
- 策略版本、MCTS 模拟数和时间上限。
- 每回合棋盘、手牌、SP、决策和 MCTS 统计。
- 胜负、双方最终墨迹。
- 每回合识别置信度和异常。
- 控制器命令、耗时、应答和重试次数。
- 人工介入次数、卡死位置和最终恢复方式。

## 当前状态与改进顺序

记牌不要求深度学习。当前已有双方已亮牌列表；本轮增加了提交动作、连续帧、
高置信度和候选间隔检查。我方确认执行的动作在回合完成时补记。
对手隐藏手牌和我方未来抽牌仍有简化顺序假设，不能称为已知真实牌序。
目前实机默认16次MCTS模拟，根候选有效上限4；这不能代表MCTS方法的能力上限。

以下是针对本项目的工程建议，不是经过统计验证的胜率门槛：

| 实机结果 | 主要动作 |
|---|---|
| 失败主要来自识别、输入或阶段切换 | 优先修完整流程，标记并隔离不确定数据 |
| 行动可靠，但策略会浪费特殊点或SP | 改进动作先验、候选保留和资源状态，固定种子对照 |
| 对局记录可靠且模拟器与实机规则已核对 | 可做价值/策略模型原型，与现有搜索基线比较 |
| 胜率低，但识别失败、输入失败或超时很多 | 不训练模型，先解决端到端可靠性 |
| 不同 NPC 和场地差异很大 | 先做场景分组分析及反制牌组搜索，而不是直接训练通用模型 |

样本数量应由要比较的效果、场景覆盖和误差要求决定，当前没有验证过一个通用的
“足够局数”。报告需明确样本数、场景和不确定性，不把模拟提升当成实机胜率提升。

## 深度模型接入方式

建议先用结构化状态做小规模原型，不要求网络重新读取截图：

1. 训练价值模型，给 MCTS rollout 提供更可靠的终局预测。
2. 用 MCTS 访问分布训练策略先验。
3. 保存候选 checkpoint。
4. 让候选模型与当前冠军、Greedy、Random 和 NPC 代理池对局。
5. 候选模型达到预先设定的胜率门槛后才晋升。
6. 继续在真实 Switch 上抽检，防止离线过拟合。

策略网络/价值网络与MCTS可以结合，AlphaZero论文给出了这种架构[1]。
这并不证明本项目能直接复制其训练效果；隐藏手牌、同时行动和可靠数据仍需单独处理。
OpenSpiel提供多种博弈环境和学习/搜索实现，可作为研究参考[2]。

当前没有已完成的训练器、模型权重或本项目训练耗时实测，不能承诺某块GPU足够或
训练能达到某个胜率。实机events日志也尚非完整、经确认的训练集。
后续样本应以match_id/turn_id保存前后状态、合法动作、根访问分布、执行确认、
亮牌证据、最终结果、识别质量及人工介入标记。自动识别的格子标签与人工确认须分开。
