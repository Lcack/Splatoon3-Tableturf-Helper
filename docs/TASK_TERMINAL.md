# 任务终端

以下命令均在项目根目录执行，`python` 指已安装本项目的解释器。

启动：

```text
scripts\open_task_terminal.cmd
```

或：

```powershell
python -m tableturf_rebuild task-terminal
```

## 任务队列

- 设置 NPC、目标难度、目标累计胜场和预设卡组后，点击“追加任务”保存本次配置快照。
- 待办任务可上移、下移或移除；已在执行的任务不随输入框修改而变化。
- 点击“开始队列”按顺序执行。空队列会先把当前输入追加为任务，等待 NPC 列表或难度菜单连续确认后开始。
- 当前任务完成后，仍需返回并确认安全菜单，才会交接下一项任务。
- “暂停/继续”控制队列执行；停止后保留任务与进度。启动程序时读取已保存队列不会自动发送按键。
- 队列及进度保存到 `profiles/task_queue.json`，属于本机运行状态，不纳入 Git。
- “调试地图”“打牌调试”“重载核心（暂停）”位于“调试”打开的窗口中。

## 任务规则

- 目标胜场是目标难度的累计胜场，不是在现有胜场上再增加指定次数。
- 解锁下一难度默认需要该难度累计3胜。
- 例如当前胜场为 `1级=3、2级=0、3级=0`，目标为难度3累计30胜，
  计划会显示为：难度2再胜3场、难度3累计30胜。
- 两次独立结算识别确认胜利后，立即更新本场NPC、难度对应的累计胜场与剩余胜场，
  同一局只计一次；返回NPC菜单后用实际三档数字核对，已确认的进度不会回退。
- 未确认的结算不会自动按A跳过。达到目标后退出继续对战，不再启动下一局。
- 结果页和奖励页要求当前页面连续确认且已稳定至少0.75秒后才按A；
  若仍在原页，间隔至少1.5秒重试，每页最多4次。发送成功不等于页面已切换。
  已确认后续页面就关闭旧页重试；当前页面还须与第一候选一致，
  防止状态机迟滞把重赛菜单误当成奖励页。次数和完成标记跨核心重载保留。
- 继续对战弹窗独立读取标题和两侧按钮文字，避免胜负背景、最终棋盘改变整图匹配分数而卡住。
  仍要求第一候选一致、候选差距达标及两次独立确认后才按菜单A；诊断显示各项文字分数与等待原因。
- 经验奖励页独立核验“占地斗士等级”标题、点数徽章、经验条和数字区域，不依赖最终棋盘背景。
  已确认比赛结果后，连续两次奖励页证据并稳定至少0.75秒才确认；每种已识别奖励子页最多4次，整段奖励最多12次，重载不清空预算。
  未标定的物品弹窗不凭整图相似度确认；结算等待超过5秒会额外保存一次现场，每局均保留自己的结算证据。
- 单按钮通知页另核验宽暗色面板、白色标题、说明文字和右下完整“A OK”提示。
  已用“追加新场地”和“对战对手等级提升”原图验证；物品奖励是否使用相同结构仍待实机验证。

## 卡组

- 启动任务终端后，如果已有预设卡组，会自动选择排序后的第一套。
- 如果检测到EasyCon串口，会自动连接并发送虚拟手柄配对序列。
- 未选择预设卡组时，任务进入卡组选择界面后会保持等待，不会自动按A。
- 选择预设卡组后，终端会在卡组界面比对15张卡的形状与SP成本；
  找到匹配卡组后按A确认。
- 每次选择“继续对局”都清除上一局的牌组确认，重新比对实际15张牌；
  配置的牌组内容不作为视觉确认。没有重新确认时，不进入自动选牌或重抽流程。
- 手牌出现预设之外的明确牌形时，取消旧动作并提示牌组不符；
  不强制把实际手牌匹配成预设中的其他卡牌，也不自动猜换完整牌组。
- “管理预设卡组”支持输入名称、模糊搜索全部266张卡、选择15张并保存。
- 预设保存到 `profiles/decks/*.json`。

## 对战自动执行

使用已保存的15张预设卡组时，终端会启用视觉闭环MCTS：

- 读取当前四张手牌及选牌焦点。
- 组装棋盘、手牌和NPC牌组为`BattleState`。
- MCTS选择普通摆放或可支付的特殊攻击动作。
- 自动移动到目标手牌、按A确认。
- 从摆放预览反推当前旋转和起点。
- 自动旋转、移动并再次按A放置。
- 每回合重新读取手牌和棋盘，最终进入结算。

普通摆放和跳过弃牌已有实机记录。特殊攻击已在武器子的Cross地图中完成
一次巨大防护罩的开启、选牌、放置与下一回合确认，不能据此宣称连续多局稳定。
特殊攻击只采用连续两帧确认的HUD余额，开启后还必须识别到“关闭特殊攻击”按钮文字，
再选牌、定位预览并确认。模式不明或开启失败时停止按键。
按钮获得焦点时文字会放大；开启/关闭识别覆盖1.00、1.05、1.10倍字形，
不依赖按钮是否随焦点变色，也不降低文字匹配门槛。
激活特殊格数量不等于可花费SP；摆放期间使用开启前保存的余额核验本次动作。

选牌焦点优先读取卡牌/按钮左下角的动画黄色小鱿鱼，覆盖四张牌及底部两个按钮，
白色三角箭头作为补充证据。菜单中的小鱿鱼必须结合菜单区域与页面判断。
每张灰牌仍读取图形和费用，
但不作为普通摆放候选；不能以其他卡牌更亮来推断焦点已移动。
同一张牌连续确认三次仍未进入摆放时，执行器停止按键并保留错误诊断。
移动/旋转要求两次一致的预览，最终放置仍要求三次；旋转持续不收敛时停止。
旋转优先取最短方向：差90°按Y，反向差90°按X，差180°逐步按两次Y。
每条旋转保存按前牌形和期望朝向，视觉确认后才发送下一步；
移动期间若朝向无故改变则等待复核，不交替发送XY。
对称牌按照含特殊格位置的等价牌形比较；人工按键释放后清除预览反馈记忆，重新观察。
点阵匹配区分本帧直接纹理、历史直接纹理与颜色背景提示；形状同分时优先直接证据。
若不同特殊格位置仍同分，则输出方向不确定并等待重读，不按遍历顺序选方向，且禁止退回棋盘读取猜测朝向。
距离目标至少5格且牌形匹配分数不低于0.95时，可同轴连续移动最多3格，
每格仍保持50ms按下和350ms释放间隔。粗移仅减少中间视觉等待，
不使用长按，也不连发放置A。路径及前方缓冲格须位于可用棋盘内；
每批结束重新确认实际预览位置，末端至少两格保持单步调整。
实际位移与预期不符时，本张牌禁用粗移。暂停会取消未发出的剩余脉冲，
继续后先重读实际位置；最终放置仍要求三帧稳定与规则核验。
没有可执行摆放时，依据实际小鱿鱼焦点移动到“跳过”；只有焦点确实位于该按钮才按A。
必须识别到“返回”文字后才选择弃牌，不能仅凭手牌变亮认定跳过已打开。
只有已发送摆放或弃牌确认后，才允许亮牌/结算识别消耗本局回合数。
即使漏看了亮牌、前后都识别为选牌，同一页面标签也可结束上一回合：
已提交动作、旧牌消失、四张新手牌及选牌焦点连续两次独立确认后，
清除旧动作并重新规划；弃牌还必须确认“返回”按钮已经恢复为“跳过”。
核心重载保留已提交摆放、特殊攻击或弃牌的待确认凭据，
只有新画面证据达标才补记回合和已用牌，不会因为重载而重复发送A。
重载也保留已完成回合与双方已确认用牌；未提交的旧动作会清除，重新读取棋盘后规划。
同一局中，选牌阶段无预览时已确认的特殊点位置会保留，避免火焰动画使它退回普通墨水。
预览覆盖区不会新增这类记录；换局、换地图或重置识别时清空位置记忆，激活状态与HUD的SP余额仍单独读取。
对于完整、高置信且稳定定位的预览，仅允许从卡形占格及其周围一格之外学习真实特殊点；
预览覆盖区继续禁止新增，避免整帧有预览就丢掉其它区域的可靠特殊点证据。
未提交A的灰色目标会按B取消一次；两次独立确认原手牌、亮选牌焦点及新棋盘后，
重新规划并排除本回合已被拒绝的卡形落点。每回合最多恢复3次，取消未确认12秒会停止。
恢复预算、排除目标及已取消待确认凭据跨重载保留；不会因灰色而按A，提交后不走这条恢复路径。
放置A之后的灰色、残缺预览或朝向变化仅用于等待回合，不再调整已提交位置。
只有原牌仍在、没有选牌焦点、完整同姿态黄色预览连续三帧稳定且冻结棋盘规则仍通过，
才允许有限放置A重试。重载的摆放凭据只确认完成，不恢复重试权限。

## 调试窗

任务终端中的“调试”按钮会打开共享EasyCon连接和采集画面的虚拟手柄窗口。
打开调试窗时任务自动按键会暂停。调试窗提供：

- 左右摇杆、方向键、ABXY、LR/ZLZR、Home、截图和加减键。
- 当前画面截图、开始/停止录像和保存目录入口。
- 右侧实时状态机识别栏，包括状态、置信度、NPC、牌组、棋盘、
  特殊攻击、选牌几何、亮牌和比赛结果。

## 直接打牌调试

调试窗中的“打牌调试”按钮可以直接从当前战斗画面启动MCTS，不需要先走
NPC、难度和卡组选择流程。使用前选择调试地图；当前预设卡组会自动作为
我方牌组，缺少NPC上下文时使用`MiniGame_Starter`作为中性对手模型。

打牌调试会暂停正式任务并复用当前采集卡和EasyCon连接。按钮再次按下即可停止。

## 实时诊断及核心重载

终端自动保存每个进程独立的诊断到 `artifacts/live_task/run-*/`，包含
`latest.json`、`terminal.log`、`events.jsonl`、当前采集 `capture.jpg` 和
对应识别结果的分析原图 `analysis.png`。读取诊断不会占用第二个采集卡或串口连接：

```powershell
python tools/read_live_task.py --tail 15
python tools/read_live_task.py --json
```

诊断记录手牌可用状态、实际焦点、地图网格校正、MCTS目标、逐格斜线/点阵候选、
形状匹配分数、预览方向、确认次数和最近发送的按键。
还包含逐阶段耗时、HUD SP余额、特攻模式文字证据和亮牌识别置信度。
比赛结果文字每帧独立检查；明确的WIN/LOSS结果优先于全局页面分类，
避免胜利页的名牌和彩纸被误当成手牌焦点。计胜仍需要两次独立明确结果。
分析原图可能早于当前采集，读取时应同时检查快照时间和分析时间。

“重载核心（暂停）”会先停止自动按键、等待当前分析完成，再加载本地视觉、
MCTS、状态机和执行器代码。窗口、采集和串口连接保留，旧规划动作及预览历史清除。
重载后需要再次点击“打牌调试”或恢复正式任务。
本轮的预览刷新修复可在重载时补入当前窗口：暂停观察的识别也改由单个后台线程完成，
界面刷新不再等待整次识别；分析只取最新帧，不积压采集帧。

## 本机画面与控制接口

任务终端启动或首次加载本轮核心后，自动监听 `127.0.0.1:8765`；
端口占用时自动换用空闲端口。实际地址、进程、会话和访问令牌保存于
`artifacts/live_task/control_endpoint.json`，也保存在该进程的 `run-*/` 目录。
暂停任务仍可读取画面和控制，关闭终端后接口停止。

```powershell
python tools/control_live_task.py status --compact
python tools/control_live_task.py frame --output artifacts/diagnostics/current.jpg
python tools/control_live_task.py pause
python tools/control_live_task.py press Y --hold-ms 120
python tools/control_live_task.py reload
python tools/control_live_task.py resume
python tools/control_live_task.py release
```

接口提供 `GET /status`、`GET /frame?kind=capture|analysis`、
`POST /commands` 和 `GET /commands/{id}`，使用 `X-Tableturf-Token` 请求头。
`press` 请求示例为 `{"command":"press","buttons":["Y"],"hold_ms":120}`。
其他命令只需 `command` 字段，命令完成状态通过回执查询。
采集画面由独立编码线程最多每秒更新5次，返回帧编号和实际帧龄；
分析原图对应最近一次诊断。该接口不会另开采集卡或串口。

手动按键先暂停自动流程、排空已有分析，再逐条发送；默认120ms，
范围30–1000ms，到时自动释放，并有独立释放计时器。
手动操作后自动对战保持暂停，需明确 `resume`。
核心重载保留接口连接，旧动作清除，重载后同样保持暂停。
控制接口自身的代码修改需要重启终端；MCTS、状态机、识别与执行器仍支持核心重载。

## 记牌及样本

对方亮牌需要本回合存在已提交动作、连续两次高置信且候选不并列，才加入已用牌记录。
我方已确认动作在回合完成时补记。未识别的牌保留未知，当前对手隐藏手牌模型仍有简化假设。
诊断日志不是完整的强化学习训练集，人工接管和识别不确定的回合不能自动作为正确策略样本。

`tools/export_preview_samples.py` 可导出点阵/斜线与冻结底图背景的逐格小图。
首批复核样本位于 `artifacts/preview_samples/background-review/`，
含中文联系表、元数据和未覆盖组合；自动预测与人工确认字段分开保存。

## 自动按键时序

- 普通自动按键按下保持50ms，释放后等待350ms再发送下一次按键。
- “连接虚拟手柄”序列为L+R两次、随后A；每次按下保持50ms，
  两次操作之间等待350ms。
- 重抽阶段固定选择“维持现状”：先按左键，再按A；
  每次进入该阶段只执行一次。
- NPC搜索先向下；连续三次名称没有变化时改为向上查找。
- 比赛结束后，如果当前难度还有剩余胜场则选择“继续”，
  当前阶段刚完成或任务目标刚达到时选择“退出”返回难度选择。
